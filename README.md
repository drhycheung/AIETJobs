# AIETJobs — Daily push of Hong Kong AI × EdTech graduate jobs

A daily automated system for **final-year BSc(AI&EdTech) students at The Education University of Hong Kong (EdUHK)** that discovers Hong Kong AI / EdTech related jobs → verifies the official links → filters for fresh-graduate fit → generates a static website → publishes it for students to reference.

**Live site:** https://drhycheung.github.io/AIETJobs/ (deployed automatically by GitHub Actions on every push to `main`)

> This repository and its live site are intended for students. The maintainer log (`REPORT.md`) and the filtering details are kept separate so they never appear on the public student page.

---

## Compliance statement (defensible in public)

This project is a non-commercial, education-purpose public information aggregation tool serving final-year BSc(AI&EdTech) students at The Education University of Hong Kong. We:

- Crawl directly only the official vacancy pages of universities; the Hong Kong Labour Department's `jobs.gov.hk` is whitelisted as an official source, but its `robots.txt` forbids automated crawling and its vacancy pages are session-token gated, so it is discovered only through public search indexing (never direct-scraped) and re-verified daily;
- **Discover employer recruitment pages through the Tavily search service**: a page on an employer's or university's own site is the official source by construction. Only approved employer domains, Hong Kong university and government sites, and individual job-board vacancies are published; a job board's own category or search page is never published. No job board is scraped and no verification challenge is bypassed;
- **Include the major Hong Kong job boards (JobsDB / CTgoodjobs / Recruit / CPjobs) in the whitelist for individual vacancies only**; because board deep links are short-lived they are re-discovered daily, and a board page that states the post has expired is withheld;
- Access at low frequency, comply with `robots.txt`, use an identifiable User-Agent with a contact email;
- Publish only job metadata and links, never the full JD text, and collect no personal data;
- Respect copyright and the wishes of each site; takedown requests are honoured immediately.

For questions or takedown requests, contact: **Dr. HY Cheung** (`hyincheung@eduhk.hk`)

## Data source whitelist

- **Official vacancy pages of Hong Kong universities** (direct crawl): EdUHK (fully implemented), HKU, CUHK, HKUST, PolyU, CityU, HKBU, Lingnan, HKSYU (framework placeholders, being connected)
- **Hong Kong Labour Department**: `jobs.gov.hk` — whitelisted as an official Hong Kong government source, but **not directly crawled**: its `robots.txt` returns `Disallow: /` and its vacancy pages are session-token gated. It appears only as a search-discovered lead, re-verified daily, exactly like the commercial boards.
- **Employer official recruitment pages** (discovered through the Tavily search service, then verified): approved employer domains in `config.EMPLOYER_DOMAINS`, plus all `*.edu.hk` and `*.gov.hk` hosts
- **Commercial job boards** (individual vacancies only; never direct-scraped): JobsDB, CTgoodjobs, Recruit, CPjobs

**Excluded** (aggregator / scraper / blog sites, never used): hiringcafe, joblum, indeed, linkedin, gradconnection, glassdoor, ziprecruiter, etc. (full list in `scraper/config.py` `EXCLUDED_DOMAINS`).

## Current status

- **14 active jobs** shown to students (snapshot 2026-10-28), filtered from **72 raw posts** (69 EdUHK official vacancy pages + 11 employer / job-board leads discovered via search, then de-duplicated). These numbers are regenerated by the daily run and will change.
- Every link passes the `is_live` liveness check; failures are marked `expired` and never shown.
- Each job carries a short description, a ⭐ fit rating for the BSc(AI&EdTech) profile, direction tags and role tags.
- Full filtering details, reasons and to-dos live in `REPORT.md` (maintainer only).

## Running

```bash
# Prepare the environment (first time)
python -m venv .venv && . .venv/bin/activate
pip install pypdf requests   # pypdf reads the official JD PDF to verify degree / experience requirements; requests is used for the optional OpenRouter summary

# Run daily (crawl -> filter -> generate JSON + HTML + report)
python -m scraper.run
```

Outputs:

- `site/jobs.json` — **the data file read directly by GitHub Pages** (in the same folder as the student page, relative path `./jobs.json`; also written to `data/jobs.json` as a working copy)
- `site/index.html` — the static job board (multi-tag display, ⭐ fit rating, short job description, dual links, anti-scam and compliance sections; at runtime it calls `fetch('./jobs.json')` and embeds a backup snapshot for local `file://` preview)
- `REPORT.md` — **maintainer log** (filtering details, to-dos and Pages deployment notes); the student page contains no "filtered / pending-review" information

> The student page no longer uses fixed five-category sections. Instead each job is dynamically tagged (direction: Artificial Intelligence / Educational Technology / Data Analysis / Multimedia / Teaching; role: University / Industry / Intern-Trainee / Fresh-graduate friendly), so a direction that temporarily has no jobs does not make the layout look odd.

## Architecture

```
scraper/
  config.py            whitelist / excluded domains / direction-tag keywords / UA / compliance thresholds / contact
  fetch.py             force IPv4 + identifiable UA + robots parsing + is_live link check
  live.py              direct-crawl adapter for official pages (EdUHK fully implemented; other universities are framework placeholders)
  search_discovery.py  commercial-board discovery (search-API ready; reads data/discovered.json when no API is configured, never fabricates)
  pipeline.py          dedupe / multi-tag / star rating / compliance filter (with PDF text deep-check + description extraction) / sorting
  generate.py          generates site/jobs.json + site/index.html + REPORT.md
  run.py               daily entry point
.github/workflows/
  deploy.yml           deploys site/ to GitHub Pages on every push to main
AGENTS.md              maintainer / agent guide (compliance red lines, pitfalls, workflow)
REPORT.md              per-run maintainer log
data/                  working data (full job records, discovered leads)
site/                  the published static site (index.html + jobs.json)
```

## Deployment (GitHub Pages reads the data directly)

The student page `site/index.html` calls `fetch('./jobs.json')` on load, so the **`site/` directory** is deployed as-is with no build step:

1. The repository `AIETJobs` is public at https://github.com/drhycheung/AIETJobs.
2. `.github/workflows/deploy.yml` uploads the `site/` folder and deploys it to Pages on every push to `main` (uses the built-in `GITHUB_TOKEN`; no secrets to configure).
3. The generator writes the data to `site/jobs.json` (same folder as `index.html`), so the relative path `./jobs.json` resolves on Pages; every commit updates the page data.
4. Live site: https://drhycheung.github.io/AIETJobs/

## Quality red lines (filtering details are in REPORT.md)

Any job that is "likely dead / unverifiable / hits a compliance prohibition" is either withheld for the day or flagged "⚠️ pending review" rather than pushed as a dead link, fake post or violating content. In the current run, 9 jobs are shown to students out of 64 raw crawls, the rest filtered for "requires PhD / senior experience / off-direction"; filtering details are written only to `REPORT.md`, never to the student page.
